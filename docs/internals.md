# 編輯器內部運作

這份文件記錄編輯器各部分的設計與實作細節，給想了解或修改程式的人看。使用者操作請看 [README](../README.md)。

## 編輯區

編輯區是**自己繪製**的（`ui/src/editor/`），不使用 egui 內建的文字框：文字放在 rope 緩衝區，每一幀只排版、繪製看得到的那幾行，所以檔案再大，成本也只和視窗高度有關（測試以 100 萬行的文件驗證）。

- 行號固定在左邊；目前這一行有淡色底；Tab 以 4 欄為一格展開顯示（檔案裡仍是 Tab 字元）。
- **依欄位排版**：每個字元固定佔「欄寬 × 半形字寬」，中文與全形字一律剛好兩欄，不管中文字型本身的字寬是多少，上下行的英數字都會對齊（只靠等寬的拉丁字型做不到這點，因為中文字來自另一個字型）。半形英數字整串排、其餘字元逐字排並置中在自己的格子裡。
- 游標以「字」為單位移動：組合字元、emoji（含 ZWJ 序列）算一個字；中日韓全形字佔兩欄。上下移動會記住原本的欄位。
- 快捷鍵：方向鍵、Home／End（第一次按到第一個非空白字元，再按到行首）、Ctrl＋Home／End、Page Up／Down、Ctrl＋方向鍵（以詞為單位）、Shift＋以上（選取）、Ctrl+A、Ctrl+Z、Ctrl+Y（或 Ctrl+Shift+Z）、Ctrl+X／C／V、Tab／Shift+Tab。Enter 會沿用上一行的縮排。滑鼠：點擊、拖曳選取、雙擊選詞、三擊選行、Shift＋點擊延伸選取。
- **行操作**：Alt＋↑／↓ 上下移動行、Shift＋Alt＋↑／↓ 複製行、Ctrl+Shift+K 刪除行、Ctrl+/ 註解切換（依副檔名決定符號，全部已註解就取消）、Ctrl+] ／ Ctrl+[ 縮排／反縮排；選取跨多行時 Tab／Shift+Tab 整段縮排。每個操作是一個復原步驟，選取會跟著文字移動。
- **多重游標與矩形選取**：Ctrl＋點擊加上（或移除）游標、Ctrl+Alt＋↑／↓ 在上／下一行加游標、Ctrl+D 選取游標下的詞並逐次加入下一個相同的文字、**Alt＋拖曳**矩形選取（依顯示欄位，中文算兩欄）、Esc 回到單一游標。輸入、刪除、Enter、貼上、移動、複製與剪下都套用到每個游標，一次動作是一個復原步驟；貼上時剪貼簿的行數剛好等於游標數就一個游標一行。復原、取代、巨集等外部改動會讓多重游標作廢。
- **自動換行**：設定面板的開關。依顯示欄位折行（英文單字不切開、中日韓字元之間可折、避頭點不落在行首），行號只標在每一行的第一列，上下鍵、Home／End、滑鼠都以畫面上的列為單位；折行處的游標可以停在上一列的尾端或下一列的開頭（點在列尾或按 End 會停在上一列）。超過 100,000 行的檔案不提供自動換行（每次修改都要重算整份文件的列數）。
- **語法上色**：依副檔名（Rust、C/C++、Java/C#、JavaScript/TypeScript、Python、Go、Shell、SQL、CSS、Lua、JSON、TOML/INI/YAML、HTML/XML、Markdown），標出註解、字串、數字、關鍵字、型別、函式名稱；區塊註解、三引號字串、樣板字串可跨行。字串裡的內嵌運算式也會當成程式碼上色：JavaScript／TypeScript 樣板字串的 `${…}`、Python f-string 的 `{…}`（`{{` 是跳脫，不算）、Shell 雙引號字串的 `${…}`；運算式裡的字串與巢狀樣板字串都會配對，運算式也可以跨行。三引號的 f-string 目前不處理。這是輕量的分詞，不是完整的語法分析。超過 20,000 行的檔案改成只往回看 1000 行估計跨行狀態。
- **選擇語言**：狀態列（編碼的左邊）有「語言」下拉清單，列出內建與自訂語言，另有「自動」與「純文字」。選擇只屬於這個分頁，不寫進檔案；重新載入不會改變它。「自動」的規則：有檔名就依副檔名；**還沒存檔、沒有檔名**時看開頭內容猜：`#!` 直譯器行（Python、Node、Lua、各種 shell）、`<?php`、`<!DOCTYPE html`／`<html`／`<?xml`／`<svg`、以 `{`／`[` 開頭的 JSON；猜不出來就不上色（例如貼上一段沒有特徵的 Rust 程式碼，要自己從清單選）。手動選了語言，Ctrl+/ 的註解符號也跟著語言走。
- **自訂語言**：在設定資料夾下的 `syntax` 資料夾（Windows `%APPDATA%\feditor\syntax\`）放 `*.conf`，一個檔案一種語言，重新啟動後生效；自訂語言優先於內建語言（可以用來改掉內建的關鍵字）。壞掉的檔案會略過，並在輸出面板顯示原因。範例見 `examples/syntax/php.conf`。內容是 `key = value`，`#` 開頭的整行是註解：

  | 設定 | 說明 |
  |---|---|
  | `name` | 語言名稱（必填） |
  | `extensions` | 副檔名，逗號或空白分隔；也可以寫完整檔名，例如 `makefile`（必填） |
  | `line_comment` | 行註解符號，可以多個，例如 `//, #` |
  | `block_comment` | 區塊註解的開頭與結尾，例如 `/*, */` |
  | `quotes` | 字串的引號字元，例如 `", '`（沒寫就是 `"` 與 `'`） |
  | `keywords` | 關鍵字，逗號或空白分隔，可以寫多行（會合併） |
  | `capital_types` | `true` 時，大寫開頭的識別字標成型別 |
  | `case_insensitive` | `true` 時，關鍵字不分大小寫（SQL） |
  | `triple_quotes`／`backtick_strings` | 三引號字串（Python）、反引號字串（JavaScript），可跨行 |
  | `interpolation` | 字串內嵌運算式的開頭與結尾，例如 `${, }`（JavaScript）、`#{, }`（Ruby）、`{, }`（Python f-string） |
  | `interpolation_in` | 哪些字串裡有內嵌運算式，逗號分隔：`backtick`（反引號字串）、`double`（雙引號字串）、`fstring`（帶 `f` 或 `$` 前綴的字串，`{{` 視為跳脫）。沒寫就是 `backtick, double` |
  | `mode` | `code`（預設）、`markup`（HTML/XML）、`markdown`、`config`（ini／toml 的 `[區段]` 與「鍵 =」） |
- **復原**以「一段操作」為單位：連續打字、連續刪除各算一步；單次取代、全部取代、整支巨集各是一步。
- **輸入法**：組字中的文字畫在游標處並加底線，**不會進入緩衝區**，所以組字時不會污染復原歷史；候選窗貼在組字處。組字中的方向鍵由輸入法自己處理（選字），滑鼠點到別處會結束組字；點到視窗裡不能輸入的地方（空白處、按鈕）會維持組字，焦點被別的輸入框取走時，組字的內容會直接寫進編輯區。游標位置依輸入法的行為推算（Windows 內建注音只回報「被標示的一段」，游標要由文字變化與重複事件推得）。輸入法行為異常時，可設定環境變數 `FEDITOR_IME_LOG=記錄檔路徑` 再啟動，編輯區會把輸入法事件與當時的游標、組字狀態追加寫入該檔案（沒設定就不會寫任何東西）。
- 目前的限制：單行極長（數十萬字元）時該行會變慢；行數超過約 1,000,000 時垂直捲動的位置有 f32 精度限制（實測 400 萬行、346 MB 的檔案開啟約 4.5 秒、佔用約 840 MB，可以操作，但行與行之間的間距會出現肉眼可見的抖動）；Windows 的輸入法有焦點時，部分 Ctrl+Alt＋字母的組合會被輸入法吃掉而到不了編輯器。

## 尋找與取代的細節

### 尋找與取代

- **鍵盤只管兩個輸入框**：在搜尋框或取代框裡按 Tab（或 Shift+Tab），只會在這兩個框之間切換（取代列收著時，會順便把它展開）；其他按鈕（選項、上一筆／下一筆、取代、關閉…）預設都用滑鼠點，不會被 Tab 聚焦。
- 三個選項：規則表達式、區分大小寫（預設不區分）、完整單字。輸入時即時搜尋，顯示「第幾筆／總筆數」；找不到會繞回另一端並提示「已繞回」。
- 滑鼠停在「規則表達式」按鈕上會出現語法速查表與完整說明的連結（<https://docs.rs/regex/latest/regex/#syntax>）；滑鼠移到提示框上它也不會消失，可以直接點連結。
- **規則表達式**使用 Rust `regex` 語法（保證線性時間，不會被寫壞的規則卡死）；`^`、`$` 以「行」為單位。取代字串可用 `$1`、`${名稱}` 代入群組，`\n`、`\t` 代表換行與跳位，字面的 `$` 請寫 `$$`。
- **完整單字**：比對結果的前後不可緊鄰字母、數字或底線。中文沒有空格分詞，相鄰的漢字會互相阻擋，所以對中文詞通常不適合開這個選項。
- 取代與巨集造成的修改都可以用 Ctrl+Z 復原、Ctrl+Y 重做：單次取代、全部取代、整支巨集各是一個復原步驟。
- 檔案超過 8 MiB 時不統計總筆數（顯示「—」），避免每次輸入都掃描整份大檔案；統計上限 9999 筆。
- 找到的那一筆會直接成為編輯區的選取範圍（接著打字就是取代它）；「下一筆」從選取的尾端、「上一筆」從選取的開頭算起，所以自己點一下游標再按 F3，會從游標位置繼續找。Esc 關閉尋找列後，游標回到編輯區。

### 在檔案中尋找

Ctrl+Shift+F 展開面板（會帶入選取的文字與目前檔案所在的資料夾）：搜尋文字、三個選項（區分大小寫、完整單字、規則表達式）、資料夾、檔名過濾（例如 `*.rs;*.toml`）。搜尋在背景執行，可隨時停止；結果點一下就開啟（已開著就切過去）並選取符合的文字。

- 讀檔時自動偵測編碼（Big5、UTF-16 等都能搜）；含 NUL 的二進位檔、超過 20 MiB 的檔案、`.git`／`target`／`node_modules` 資料夾會略過。
- 一行只列第一個符合的位置；最多 5000 筆，超過會提示縮小範圍。


## 預覽

某些文字檔可以用不同的形式呈現。按工具列的**眼睛**（Ctrl+Shift+P），會在目前窗格的右邊開一個**預覽窗格**，顯示**目前有焦點的文件**的預覽；換窗格、換分頁、改文字都會跟著更新（文字改了之後停 0.3 秒才重新轉換，轉換在背景執行，不會卡住畫面）。內建支援：

| 檔案 | 預覽的樣子 |
|---|---|
| Markdown（`.md`、`.markdown`） | 標題、粗體／斜體／刪除線、行內程式碼、連結（網址可以點）、清單（含巢狀與核取方塊）、引用、程式碼區塊、表格、分隔線、本機圖片（相對路徑以檔案所在資料夾為準，不連網路）。原始 HTML 只認得 `<kbd>`（畫成按鍵）、`<picture>`／`<img>`（`<picture>` 依目前是深色還是淺色主題，挑 `<source media="(prefers-color-scheme: dark)">` 或 `light` 對應的圖，和 GitHub 一樣）與 `<br>`；其他標籤、`<script>`、`<style>`、註解一律略過 |
| CSV、TSV | 表格，第一列當標題列，欄寬可以拖曳；只顯示前 5000 列 |
| JSON、TOML、YAML | 可摺疊的樹，字串、數字、布林各有顏色；格式錯誤時顯示出錯的行與欄 |
| SVG | 直接顯示圖形，邊改邊更新 |

- 整個程式只有**一個**預覽窗格，所有文件共用：它永遠顯示有焦點的文件，不綁定某個窗格，關掉別的窗格它還在。預覽窗格和一般窗格一樣是圓角卡片，有自己的標題列與關閉按鈕，大小可以拖曳，也可以**拖到版面的任何位置**：拖它的標題放到別的窗格的左、右、下側；反過來，把**分頁拖到預覽窗格**的左、右、下側，就是把預覽窗格切開（分頁變成它旁邊的新窗格），放進中間則不行，預覽窗格不收分頁。拖曳時有預覽範圍，Esc 取消。**預覽窗格也能取得輸入焦點**：點一下預覽窗格（框線會變成強調色），Ctrl ＋／－、Ctrl＋滾輪、Ctrl＋0 調整的就是預覽的字級（和編輯區的字級各自獨立）；點回編輯的窗格或換分頁，焦點就回到編輯區。檔案要有副檔名（沒存過的文件沒有預覽），超過 5 MB 的檔案不預覽；窗格太窄（放不下兩個最小窗格）時開不了。

## 分頁、窗格、工作階段與外部變更

- 新增或開啟檔案會開在新分頁；目前是空白未修改的文件就直接用它，已經開著的檔案會切過去而不是重複開。每個分頁各有游標、選取與復原歷史。關閉視窗時，只要有分頁未儲存就會逐一詢問。
- **雙按分頁重新命名檔案**：會跳出對話框，預設只選取主檔名（副檔名不會被蓋掉），按 Enter 或「重新命名」就真的把磁碟上的檔案改名（留在同一個資料夾）。檔名不合法（空白、含 `\ / : * ? " < > |`、Windows 保留名稱）、資料夾裡已經有同名檔案、或別的分頁已經開著那個檔案時，會在對話框裡說明原因，不會覆蓋。有未儲存修改的分頁也可以改名，內容與未儲存狀態不變。還沒存成檔案的分頁，雙按會開「另存新檔」。
- **分割窗格**：把分頁拖到編輯區的**左側、右側或下側**（拖曳時會預覽新窗格佔的範圍），就往那個方向切出新窗格，分頁移進去；可以一直切下去，左右、上下任意組合。每個窗格有自己獨立的分頁列，可以再把分頁拖到別的窗格的分頁列或編輯區中間，放進那個窗格。窗格是彼此留有間隙的圓角卡片，間隙就是分隔線，可以拖曳調整大小。
  - **最小窗格**：窗格不會小於 240×140 點（分隔線拖不過去）；太小而無法再切成兩個合格窗格的那一側，就不會出現切割區。
  - 分頁是「搬」不是「複製」：同一份文件不會同時出現在兩個窗格；已經開著的檔案再開一次，會切到它所在的窗格。
  - 有一條強調色線的是**有焦點的窗格**（在窗格上點一下就會換）；尋找、儲存、巨集、狀態列都作用在它目前的分頁。
  - 窗格裡最後一個分頁關掉時，窗格一起關掉；也可以按窗格分頁列右端的按鈕直接關閉窗格，裡面的分頁（包含未儲存的修改）會移到相鄰的窗格，不會關掉任何文件。
  - 拖曳途中按 Esc 取消。目前沒有「上側」切割，也不能在同一個窗格內拖曳排序分頁。
- **工作階段**：不帶檔名啟動時，會把上次開著的檔案（與游標位置）開回來。記在設定資料夾的 `session.conf`；沒存過的空白文件不記。**窗格版面也會記住**：關閉再重開，所有窗格（包含各自的分頁、作用中的分頁、游標位置、分隔線比例、有焦點的窗格與預覽窗格）都會還原；已經不存在的檔案會略過，沒有檔案可開的窗格就不再出現。
- **外部變更偵測**：用系統的檔案監看（`notify`）盯著所有已開啟檔案所在的資料夾，涵蓋每個窗格的每一個分頁（視窗拿回焦點時與每 5 秒也會檢查一次當後備）。檔案被別的程式改了：沒有未儲存的修改就自動重新載入並保留游標位置；有的話，作用中的分頁會詢問是否重新載入（選擇保留就不會一直再問），背景分頁則在標籤標上「（磁碟上已變更）」，切過去時再問。檔案被刪除或移走：標籤標上「（已刪除）」並在輸出面板提示，內容仍保留，存檔會重新建立檔案。

## 終端機

- 工具列的 `>_`（`` Ctrl+Shift+` ``）新增一個終端機，執行系統預設的 shell（Unix 用 `$SHELL`；Windows 優先 PowerShell 7，其次 Windows PowerShell，最後 cmd）。起始資料夾是目前文件所在的資料夾。**終端機是一種分頁**，標籤只用名字「終端機 1」「終端機 2」…（關掉的編號會被回收），雙按標籤可以自己取名（留空改回預設）：新的會在有焦點的窗格下方切出新窗格；標籤可以像文字分頁一樣拖——拖到別的窗格中間就加入那個窗格的標籤列，拖到窗格側邊就切成新窗格；切到別的分頁時，shell 照常在背景執行。可以開很多個。`` Ctrl+` `` 讓焦點依序在各個終端機之間循環，繞完一圈回到原來的分頁（還沒有終端機時就新增一個）。shell 結束（輸入 `exit`）或按標籤的 ×，那個分頁就關掉，其他的不受影響。
- 偽終端機與跳脫序列（顏色、游標移動、全螢幕程式）由 `alacritty_terminal` 處理。**終端機分頁會記進工作階段**：重開後每個窗格依原本的順序開回檔案與終端機分頁，終端機取同樣的名字、作用中的分頁位置也一樣；但每個終端機是新開的 shell（先前的輸出與執行中的程式還原不了），起始資料夾是該窗格第一個檔案所在的資料夾。
- 輸入：一般按鍵、方向鍵與功能鍵、Ctrl＋字母（Ctrl+C 在有選取文字時是複製，否則中斷程式）、貼上（括號貼上模式）、輸入法；滑鼠拖曳選取、滾輪捲動（全螢幕程式裡滾輪改成方向鍵）。
- 顏色來自目前的配色方案（16 色、預設文字與底色）。文字和它所在底色的對比低於 3:1 時（例如深色底上的深灰字、淺色底上的淺黃字），會自動把文字往看得清楚的方向調整，顏色對比夠的原封不動；方塊、表格線、Powerline 符號等圖形字元不調整。可以用 `examples\terminal-colors.ps1` 檢查顏色與這個保護（第 10 段）。
- 目前沒有：滑鼠事件回報給程式、連結點擊、搜尋、分頁式多個終端機、字級獨立調整（用編輯區的等寬字）。

## 工作階段檔案格式

工作階段存在設定資料夾的 `session.conf`，格式很簡單，一行一個 `key = value`：

```text
focus = 2
layout = H0.5[P0,V0.4[P2,W3]]
preview = 3,2
pane = 0
active = 1
file = C:\專案\a.txt<Tab>120
terminal = 1<Tab>2<Tab>編譯
pane = 2
active = 0
file = C:\專案\b.md<Tab>0
```

- `layout` 是窗格版面：`P` 是一般窗格、`W` 是預覽窗格、`H`／`V` 是左右／上下分割（括號前是第一個子節點佔的比例）。`preview = 預覽窗格,它預覽的窗格`。
- 每個 `pane = N` 之後的 `active`、`file`、`terminal` 屬於那個窗格。`file` 是 `路徑<Tab>游標位置`；`terminal` 是 `分頁位置<Tab>編號<Tab>名字`（名字可以是空的，表示預設的「終端機 N」）；`active` 是作用中的分頁位置，檔案與終端機合在一起算。
- 沒存過檔的空白文件不記；舊版只有一串 `active`／`file`（沒有 `pane`、`layout`）的檔案會當成只有一個窗格。還原時已經不存在的檔案略過，沒有分頁可開的窗格從版面拿掉。

## 外部變更偵測的實作

- 用 `notify` 監看所有已開啟檔案所在的資料夾（不遞迴）。事件只當成「有事發生」的訊號，不分析是哪個檔案——事件裡的路徑在各平台寫法不一致（大小寫、符號連結、macOS 的 `/private`），直接比對不可靠。訊號會先去抖動 250 毫秒，再逐一比對每個文件的修改時間（只是幾個 `stat`）。
- 視窗拿回焦點時與每 5 秒也會檢查一次，當網路磁碟或監看失效時的後備。
- 沒有未儲存修改的分頁直接重新載入；有的在 `Document::disk_state` 標成 `Stale`，切過去時才詢問。檔案消失標成 `Missing`（只回報一次），重新出現時恢復。實作在 `ui/src/watcher.rs` 與 `ui/src/document.rs`。

## 終端機的實作

- 偽終端機（Windows 的 ConPTY、Unix 的 pty）、背景讀寫執行緒與跳脫序列的解析都交給 `alacritty_terminal`；我們只負責挑 shell、改變大小、把按鍵翻成位元組（`ui/src/terminal.rs`）以及用 egui 把格子畫出來（`ui/src/terminal_pane.rs`）。
- 終端機放在 `Document::terminal`：它跟著 `Document` 一起在分頁、窗格之間搬動，所以拖放、切割、關閉都直接沿用分頁的機制；作用中的分頁是終端機時，窗格畫的是終端機畫面，不是編輯區。分頁不在前景時 shell 仍在背景執行。
- 鍵盤焦點用 egui 的焦點機制：終端機的畫面元件有焦點時，這一幀開頭把按鍵、文字、複製貼上與輸入法事件從輸入裡取走送給 shell，所以編輯區與全域快捷鍵不會收到（開關終端機的 Ctrl+ 例外）。
- 網址與搜尋：畫面上折行的幾列（行尾有 `WRAPLINE`）算同一個「邏輯行」，所以網址和搜尋字串都可以跨越折行。按住 Ctrl 時才會去找滑鼠底下的網址（只掃那一個邏輯行）；搜尋則掃描整個終端機（含歷史），字串改了或每 0.4 秒重掃一次，因為輸出會一直變。這兩件事的純文字部分在 `ui/src/terminal_text.rs`（網址辨識：協定、尾巴的標點與沒配對的括號；不分大小寫的比對），畫面與捲動在 `ui/src/terminal_pane.rs`。
- 滑鼠：程式用 `ESC[?1000h`／`1002h`／`1003h`要求回報（按下與放開／加上拖曳／加上所有移動）、`1006h`要求 SGR 格式時，滑鼠事件換算成格子座標送給程式（`terminal::encode_mouse`）；傳統格式的座標超過 223 的格子送不出去。滾輪在回報模式下送成按鍵 64／65。按住 Shift 時不回報，照一般終端機的做法選取文字。沒有要求回報時，拖曳是選取、滾輪是捲動歷史（全螢幕程式裡改成方向鍵）。
- Shell 清單：Windows 檢查 PATH 裡的 `pwsh.exe`、`powershell.exe`、`cmd.exe`、`wsl.exe`、`nu.exe` 與幾個常見的 Git Bash 位置；其他系統用 `$SHELL` 加上 `/etc/shells` 裡實際存在的（同名的只留第一個）。每個終端機在新增時就記下自己的 shell（`TerminalPane::shell`），之後改設定不影響已經開著的。實作在 `terminal::shells_for`（純函式，有測試）。
- 顏色：16 色來自配色方案（`term_*`），其餘 256 色是標準色，真彩色原樣畫；文字和底色對比低於 3:1 時往看得清楚的方向調整（保留色相），方塊、表格線、點字、Powerline 符號不調整。`examples/terminal-colors.ps1` 可以檢查。

## 介面語言的實作

- 英文對照表在 `core/src/i18n/en.rs`，以中文原文當 key：程式裡用 `t("中文")` 與 `tf!("…{}…", 參數)` 取字串。有一個測試會掃描原始碼，確認每個字串都有英文、對照表沒有沒用到的字串、參數的名稱與順序一致。所以新增任何介面文字都要同時補英文，否則測試會失敗。
- 目前翻譯的是介面文字、提示與訊息；README 之類的文件與錄製出來的巨集檔內的註解不受影響。「跟隨系統」依作業系統的語言決定（中文系統用中文，其他用英文）。
