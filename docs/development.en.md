# Development guide

## Project layout

| Path | Description |
|---|---|
| `core/` | `feditor-core`: text buffer (ropey) with undo/redo, file encodings, search, line wrapping, search in files, and the interface language (Chinese/English table). Independent of the UI and macro engines |
| `script/` | `feditor-script`: language-agnostic macro API (`EditorApi`, `ScriptEngine`) |
| `script-js/` | `feditor-script-js`: JavaScript macro engine (QuickJS via rquickjs) |
| `ui/` | `feditor`: egui front end, including the custom-drawn editor area (`ui/src/editor/`), tabs and split panes (`panes.rs`, `pane_ops.rs`), preview (`preview*.rs`), terminals (`terminal*.rs`), file watching (`watcher.rs`), macro library, syntax highlighting, and session restore |
| `examples/` | Example macros (`macros/`) and test files in various encodings (`files/`) |
| `proto/` | Standalone IME verification prototypes (egui, iced, Slint); not part of the main workspace |

## Design decisions

- **Rust core**: performance, single-binary distribution, cross-platform builds.
- **Custom-rendered UI with egui**: Traditional Chinese IME has been verified on egui (see `proto/IME-TEST.en.md`). The editor area does not use egui's `TextEdit`; it is custom-drawn (rope buffer plus painting only the visible lines) because `TextEdit` is not fast enough for large files and gives no fine control over undo and IME composition.
- **JavaScript first for macros** (`rquickjs`): lightweight, statically linkable, and easy to cap in time and memory. It sits behind the `ScriptEngine` abstraction, so adding Python or another language later does not touch the core.
- **File size target**: up to a few hundred MB. Buffer and rendering will be optimized later if larger files are needed.

## Building and testing

```powershell
cargo test --workspace                          # all unit tests
cargo run --release -p feditor                  # start the editor
```

- **Tools needed**: Rust (stable). On Windows you need the MSVC toolset and the Windows SDK (installing the C++ workload of "Build Tools for Visual Studio" is enough); the system packages needed on Linux are listed in `.github/workflows/ci.yml`, and other distributions may need adjustments.
- **Tests**: the UI tests drive the whole `App` with a headless egui (tabs, panes, drag and drop, sessions, preview, terminals, ...); one terminal test really starts a shell. A test scans the source to make sure the translations are complete (see [How the editor works](internals.en.md)).
- **Bilingual documents**: documents (the README, CHANGELOG and the files under docs) are always provided in both Traditional Chinese and English, with the English version carrying an `.en` suffix and both files starting with a language switch link; when you change one, update the other.
- **The application icon** (a text document with a pencil) is generated by `ui/assets/make_icon.py`: `uv run ui/assets/make_icon.py`.
- **Checking terminal colors**: run `examples/terminal-colors.ps1` inside the terminal (`-Only 1,2` runs only the chosen sections).

## Releasing

- The GitHub Actions configuration is in `.github/workflows/`: on a push to `main` CI runs the tests and the build on Windows, macOS and Linux; pushing a `vX.Y.Z` tag triggers the Release workflow, which produces `feditor-windows-x64.zip`, `feditor-macos.dmg` and `feditor-linux-x64.tar.gz`.
- To release a new version: update the version in `Cargo.toml` (the workspace and the dependency versions between crates), turn "Unreleased" in the CHANGELOG into the new version with a date and add the link, wait for CI to pass, tag it, and then add bilingual release notes to the Release.
- The macOS build is not notarized, only ad-hoc signed, and Apple Silicon only; CI checks that the `.app` and `.dmg` are packaged completely.

## Notes on the development environment

- On one development machine the wgpu **Vulkan backend crashes** (`0xC0000005`). On Windows DX12 is used by default instead; the `WGPU_BACKEND` environment variable overrides it.
- The IME has only been verified on Windows + DX12. When IME behavior looks wrong, set the environment variable `FEDITOR_IME_LOG=path/to/log` before starting, and the editor appends the IME events together with the caret and composition state at the time to that file (nothing is written if it is not set).
- If another `link.exe` (for example coreutils') comes before MSVC's on the Windows PATH, Rust linking fails; make MSVC's come first, or build from a "Developer Command Prompt" (vcvars).
- `proto/` holds standalone IME verification prototypes (egui, iced, Slint) that are not part of the main workspace; the results are recorded in `proto/IME-TEST.md`.
